## 安装记录

1. 配方 reset 到 v1.7.0;`./start.sh update`:引擎 c1ce6491 安装顺利,pinned FlashInfer 恢复逻辑生效(我们 issue #5 反馈的陷阱已被官方修复)。
2. **flashinfer-cubin 0.7.0 下载陷阱**:0.7.0 的 wheel 不在 PyPI(PyPI 最新 0.6.9)也不在 flashinfer.ai 索引页(那里只有 jit-cache 系列),实际托管在 GitHub Releases(v0.7.0 assets,cubin 为 1,494 MB 单文件)。慢速链路建议从 Releases 直下后本地安装。
3. **BOOT_CHECK 时序 bug(已报上游)**:engine 未就绪时 `--log-only` 轮询发真实请求,URLError 后直接 stop 整个 checkout,正常启动被误杀。`BOOT_CHECK=0` 绕过,手动完成等价两个 temperature-0 验证。
4. **环境占用坑**:一次启动失败的真实原因是 TensorFold POC 服务占用 GPU0 20 GB(数小时前遗留),cuda:0 空闲低于 0.95 门限 → WorkerProc 拒绝启动。排查时易误判为引擎问题。

## cmpunlocker 二期

- 本机驱动原为旧版 cmpunlocker 610.43.03(仅功耗/Gen2 解锁,无 ForceP2P)
- 安装 Morrowmake fork:`sudo ./install.sh --p2p --profile=8gb --no-iommu --no-passthrough`
  - 坑①:系统默认 gcc 11 不认内核 flag `-ftrivial-auto-var-init=zero`,`driver/build.sh` 的 `CC_CMD` 需改 gcc-12
  - 坑②:`ForceP2P=0x11` 写入 modprobe conf 后需重启生效
- 重启后:**SM 70 → 74(四卡)**;`tools/p2p-content-check.py` **108/108 PASS**(9 尺寸 × 12 有序对,字节级比对)——x4 矿机首次打通 GPU peer

### 发现

1. **1.7.0 新内核对 coding 文本 +22.6~31%**(compiled Marlin decode、tuned GEMM/mHC 与代码文本的投机正循环);structured/prose/长输入持平。
2. **c8 回退依赖 SM 数**:70 SM 下 1.7.0 聚合 −6.3%,74 SM 下消失——70SM+1.7.0 组合问题,已连同归因报上游。
3. **P2P 在 Gen2 x4 上为聚合负优化**:开启后 −13.6%(522.9 vs 645.3)。带宽不足时 P2P 序列化/等待开销超过省掉的 host 拷贝,与 PixelML 在 PLX 拓扑的观察一致。生产锁定 `P2P=off`(74 SM 与 P2P 同模块,P2P off 保留 74 SM)。
4. P2P verified check 机制本身按设计工作:x4 上正确探测并降级/启用,行为与文档一致。
